# Healer v1 完整交付规格与执行计划

用户授权在本工作区全权完成项目，学习后置；目标为可运行、可复现、可展示且可被面试追问的完整个人项目。沿用 codex/safe-healing 分支，不改变其他项目源码或求职主表。

## 架构与验收

1. 保留 Step/Target 与执行器分层。规则补全基于独立目标约束的确定性候选，文字和属性安全转义；歧义、关键页面、不可操作仍拒绝。模型不得改目标或断言。保留历史数据，新版同场景重新评估，若规则已覆盖则如实记录零模型收益。
2. 模型客户端支持有界请求超时、全局调用上限、有限瞬态重试（连接/超时/429/5xx），记录每次尝试及用量。鉴权错误和非法响应不无限重试；不记录密钥。成本无可靠价格时为未知，允许调用方显式提供价格表。
3. 测试计划可从 JSON 文件加载；原计划深拷贝，修复不静默写回。操作之后支持精确元素文字、数量、值和属性断言；断言失败不修复。命令区分生成计划和执行计划，纯规则执行不要求模型密钥。
4. 生成计划可使用只读页面快照作为依据，输入页面内容是数据而非指令；生成校验失败把具体错误反馈给模型。输出计划供查看和复用，不假称全站自主探索。
5. 每次运行独立目录：原始计划、结果 JSON、修复审计、修复后计划建议、HTML 报告、浏览器 trace。成功、失败、无法验证和模型不可用清楚区分。初始化或生成失败也输出失败结果，CLI 非零退出。报告不得泄露输入密码或表单值；完整原计划与 trace 作为本地私有证据保留并明确边界。
6. HTML 报告可直接在浏览器打开：结果、步骤、拒绝原因、成本状态和证据链接；所有文本转义，结果可独立理解。
7. 工程交付含 pyproject.toml 的安装和 healer 命令入口、离线可复现示例、GitHub Actions 的测试、依赖和 Chromium 安装；自动检查不调用真实模型、不启动原数据库。
8. 最终跑全量测试、CLI 成功与失败用例、三模式复测、真实模型生成 smoke、ShopHub 独立临时库真实流程、trace 与报告检查；更新 README、项目进度、架构和简历素材（不改简历母版），提交并推送。

参考：Playwright Python locators / other-locators / trace-viewer；智谱对话补全官方接口。未承诺企业线上收益、零误修概率、任意网站无配置通用化。
