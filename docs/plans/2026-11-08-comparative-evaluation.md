# 对照评估与 ShopHub 实测计划

用户已批准上一轮提出的三步，并授权全权负责；继续使用当前开发分支。

目标：同一场景、同一初始状态，对比关闭自愈、纯规则、规则加真实模型；随后验证实际 ShopHub 前端和后端的商品/店铺/数量闭环，留存浏览器回放。

采用仓库内固定标注场景，避免只看已有七个示例；不使用随机生成数据充数。三种模式各用新浏览器上下文，分别报告目标正确、操作恢复、业务验证、拒绝、模型错误、token 用量和耗时。规则不可恢复的样本也保留，不为了抬高模型收益弱化安全约束。模型请求设全局次数上限，失败单列，未调用不能算模型成功。费用缺少当前可靠价格时保持未知。

ShopHub 用现有源码和虚拟环境启动独立服务；新建随机命名的 healer_eval_ 临时库，直接使用已有 DDL 和种子初始化，不调用硬编码 shop 库的 init_db，也不调用 reset。登录后人为使旧定位器失效，校验唯一正确店铺商品的实际加购、API 回读以及购物车页面数量； finally 终止自建进程、删除仅本轮拥有的临时库。保留结果和 trace，清理临时运行日志。

参考：https://playwright.dev/python/docs/trace-viewer 、https://docs.bigmodel.cn/api-reference/模型-api/对话补全 。
