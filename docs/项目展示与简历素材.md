# Healer 项目展示与简历素材

定位：AI 增强 UI 自动化与安全自愈工具，个人项目，与 AI 协作开发。该文件记录可验证的项目材料，不等于确认任何个人独立贡献；不修改简历母版，不将本地实验称为企业生产成果。

## 可选择的三条项目描述

- 基于 Python、Playwright 和结构化步骤模型构建可复用的 UI 自动化执行工具，接入页面证据辅助的测试计划生成，支持计划保存、离线执行、精确业务断言及失败中止。
- 实现规则优先的定位自愈，将独立商品/店铺/文字约束同时用于原定位器和修复候选核验，对歧义、不可操作及敏感步骤拒绝自动修复，保留原断言与修复审计。
- 建立关闭自愈、纯规则和规则加模型的固定场景对照，区分操作恢复与业务正确性；在 ShopHub 真实前后端验证自愈加购的店铺、商品及数量，提供 HTML 报告、浏览器回放和离线自动检查。

若简历篇幅有限，优先保留安全闭环、真实业务验证和对照方法，测试数量与模型名不是主要亮点。量化内容以 docs/v1-delivery.md 对应版本的真实数据为准，不能把历史 30/33 与新版结果拼成同一实验。

## 已有的可展示证据

1. `healer demo`：旧按钮编号失效，同页有另一个商品按钮，恢复后断言购物车是商品 2、数量 1。
2. `healer generate ...` + `healer run ...`：真实模型生成计划后，原定位器不唯一仍被目标约束拦住，规则恢复并通过原业务断言；生成快照和模型尝试记录独立保留。
3. `healer shophub ...`：真实 MySQL 和 FastAPI 后端中，店铺 1、商品 1、数量 2 的接口回读与页面核验一致，专用临时库清理有结果证据。
4. 固定评估集：规则完善后模型无需介入的场景保留原样，展示选型取舍，不把“必须使用模型”当工程目标。

## 诚实边界

不能写“生产级落地”“线上维护成本降低”“任意网站通用”“零误修”或“独立完成全部代码”。固定小样本的全通过不能推导线上概率；三次重复不是新增独立场景。模型用途是工具开发和测试辅助，不是模型训练或算法研究经历。学习、口述与个人技能核对按用户要求后置，不作为本轮开发交付的阻塞条件。
